# V2: Middleware + Blade Helpers for Experiment Variant Switching

## Motivation

Currently the consuming application must manually resolve experiment assignments in every controller that participates in an A/B test. This is repetitive, error-prone plumbing. Adding optional middleware + Blade helpers turns the common case into a one-liner while keeping the low-level `ResolveExperimentAssignment` action available for custom flows.

## Design principles

1. **Opt-in** — no existing code breaks. The new features are behind config flags and opt-in middleware registration.
2. **Middleware exposes, does not render** — middleware resolves the assignment and makes it available on the request. The view/controller still decides *what* to render.
3. **Stable public API** — `ResolveExperimentAssignment`, `ProjectExperimentContextIntoSignalProperties`, etc. remain available and fully usable.
4. **No hard dependency on Blade** — directives are registered from `GrowthServiceProvider` only when `blade.compiler` is bound.

## Feature breakdown

### 1. Config flags (`config/growth.php`)

```php
'features' => [
    'owner' => [/* existing */],
    'preset_modules' => [/* existing */],
    'experiment_middleware' => [
        'enabled' => false, // opt-in
    ],
    'blade_directives' => [
        'enabled' => false, // opt-in
    ],
],
```

### 2. Experiment middleware

**Class**: `AIArmada\Growth\Http\Middleware\ResolveExperiment`

**Registration**: the alias `growth.experiment` is always registered by
`GrowthServiceProvider::registerExperimentMiddleware()`, so it is available for
`Route::middleware('growth.experiment:slug')`. The `enabled` flag is evaluated
per request inside the middleware, not at registration time.

**Logic**:

```php
final class ResolveExperiment
{
    public function handle(Request $request, Closure $next, ?string $experimentSlug = null): Response
    {
        if (! $this->isExperimentMiddlewareEnabled()) {
            return $next($request);
        }

        // Slug resolution honours the owner scope. An unknown slug passes the
        // request through; an out-of-scope slug throws AuthorizationException.
        $experiment = $this->experimentResolver->resolveBySlug($experimentSlug ?? '');

        if ($experiment->status !== ExperimentStatus::Active) {
            return $next($request);
        }

        $subjects = $this->requestExperimentSubjectResolver->resolve($request, $experiment);

        $assignment = $this->resolveExperimentAssignment->handle(
            $experiment,
            identity: $subjects->identity,
            session: $subjects->session,
            anonymousId: $subjects->anonymousId,
        );

        $this->experimentContextManager->store($request, $experiment, $assignment);

        return $next($request);
    }
}
```

Identity/session/anonymous resolution is delegated to a
`RequestExperimentSubjectResolver` implementation, driven by
`http.experiment_middleware.*` config.

**Route usage**:

```php
Route::get('/sales', SalesPageController::class)
    ->middleware('growth.experiment:sales-page-test');
```

**Controller access**:

```php
class SalesPageController
{
    public function __invoke(Request $request)
    {
        $variant = $request->attributes->get('growth.variant');
        // or use a facade/helper
    }
}
```

### 3. Global helper & Facade

**Helper**: `experiment()` returns the current experiment context from the request.

```php
function experiment(): ?ExperimentContext
{
    /** @var ExperimentContextManager $manager */
    $manager = app(ExperimentContextManager::class);

    return $manager->current();
}
```

`ExperimentContextManager::current()` reads the `growth.experiment`,
`growth.variant` and `growth.assignment` request attributes and returns `null`
outside a request or when any of the three is missing.

```php
// Simple access:
experiment()->slug;        // 'sales-page-test'
experiment()->variantCode; // 'hero-a'
experiment()->isVariant('hero-a'); // bool
experiment()->assignmentId; // the sticky assignment UUID
```

**Facade** (optional, for testing):

```php
Growth::variantCode(); // 'hero-a'
```

### 4. Blade directives

Registered by `GrowthServiceProvider::registerBladeDirectives()` when
`blade.compiler` is bound. The `@variant` condition additionally re-checks
`growth.features.blade_directives.enabled` on every render, so it resolves to
`false` while the flag is off.

```php
// GrowthServiceProvider::registerBladeDirectives()

Blade::if('variant', static function (string $code): bool {
    if (! config('growth.features.blade_directives.enabled', false)) {
        return false;
    }

    return app(ExperimentContextManager::class)->isVariant($code);
});
```

Usage in views:

```blade
@variant('hero-a')
  <x-sales.hero-a />
@elsevariant('hero-b')
  <x-sales.hero-b />
@else
  <x-sales.default-hero />
@endvariant
```

Or for simple checks inside expressions:

```blade
@if(experiment()?->isVariant('hero-a'))
  <p>You're seeing the test variant</p>
@endif
```

### 5. Service provider registration

In `GrowthServiceProvider`:

```php
protected function registerExperimentMiddleware(): void
{
    if (! $this->app->bound('router')) {
        return;
    }

    /** @var Router $router */
    $router = $this->app['router'];
    $router->aliasMiddleware('growth.experiment', ResolveExperiment::class);
}
```

The alias is registered unconditionally. There is no `growth.experiment_middleware`
container binding and no separate `GrowthBladeServiceProvider`; the Blade
directives come from `GrowthServiceProvider::registerBladeDirectives()`.

## ExperimentContext value object

```php
final readonly class ExperimentContext
{
    // Promoted in the constructor, not the signature.
    public string $slug;

    public string $variantCode;

    public string $assignmentId;

    public function __construct(
        public Experiment $experiment,
        public Variant $variant,
        public Assignment $assignment,
    ) {
        $this->slug = (string) $this->experiment->slug;
        $this->variantCode = (string) $this->variant->code;
        $this->assignmentId = (string) $this->assignment->getKey();
    }

    public function isVariant(string $code): bool
    {
        return $this->variantCode === $code;
    }

    public function isControl(): bool
    {
        return (bool) $this->variant->is_control;
    }

    public function variantCode(): string
    {
        return $this->variantCode;
    }

    public function assignmentId(): string
    {
        return $this->assignmentId;
    }

    public function experimentSlug(): string
    {
        return $this->slug;
    }

    public function toArray(): array
    {
        return [
            'experiment_id' => (string) $this->experiment->getKey(),
            'experiment_slug' => $this->slug,
            'variant_id' => (string) $this->variant->getKey(),
            'variant_code' => $this->variantCode,
            'assignment_id' => $this->assignmentId,
            'module_type' => (string) $this->experiment->module_type,
        ];
    }
}
```

## Identity resolution strategy

The middleware needs a strategy to map the incoming request to a signals identity/session/anonymous ID. This should be configurable:

```php
// config/growth.php
'features' => [
    'experiment_middleware' => [
        'enabled' => false,
    ],
],

'http' => [
    'experiment_middleware' => [
        'subject_resolver' => null,
        'anonymous_id_source' => 'cookie',
        'anonymous_id_key' => 'sig_vid',
        'session_identifier_source' => 'cookie',
        'session_identifier_key' => 'sig_sid',
    ],
],
```

Default resolvers are provided, but the shipped configuration now hangs off `http.experiment_middleware.subject_resolver` plus the cookie/header settings shown above.

## Non-HTTP surfaces (queues, commands)

The middleware only covers HTTP. For jobs/commands, the app still uses `ResolveExperimentAssignment` directly with explicit owner context. This is by design — non-HTTP surfaces should be explicit about identity and owner scope.

## What this does NOT include

- **No rendering abstraction** — the app decides what to render per variant. No "page builder" or "variant templates" in growth.
- **No route registration** — the app registers its own routes. The middleware only acts on routes the app already owns.
- **No automatic experiment slug discovery** — the slug is explicit in the middleware argument. No magic route matching.
- **No Inertia-specific helpers** — Inertia support belongs in companion packages or the app layer. Livewire components use `AIArmada\Growth\Livewire\Concerns\InteractsWithExperimentContext`.

## Implementation order

1. `ExperimentContext` value object
2. `experiment()` helper function
3. `ResolveExperiment` middleware + container alias
4. Config flags (`experiment_middleware.enabled`, `blade_directives.enabled`)
5. Identity/session/anonymous resolvers in middleware
6. Blade `@variant` / `@elsevariant` / `@endvariant` directives
7. Config docs and usage docs
8. Tests: middleware sets context, Blade renders correct block, helper returns null outside HTTP, identity resolution variations

## Migration path

Users of the current API continue as-is. New projects enable the features in config and start using middleware + Blade. The low-level `ResolveExperimentAssignment` is never removed.
